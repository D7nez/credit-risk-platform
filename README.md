# RiskScope | مرصد المخاطر

تطبيق عربي لتقدير احتمالية تعثر سداد البطاقة الائتمانية في الشهر التالي، مع تحليل سجل واحد أو دفعة CSV ولوحة لمراقبة التنبؤات. المشروع تجربة بحثية توضح رحلة نموذج تعلم الآلة من تحليل البيانات إلى تقديم التنبؤ عبر تطبيق ويب.

> **تنبيه:** النموذج مدرّب على بيانات تاريخية من تايوان. نتائجه للتجربة والتقييم، ولا تُستخدم وحدها لاتخاذ قرار ائتماني أو قرار تحصيل أو للتواصل مع عميل.

## ما الذي يقدمه التطبيق؟

- **تحليل سجل واحد:** إدخال 19 قيمة مالية والحصول على احتمالية التعثر في الشهر التالي.
- **تحليل دفعة:** رفع CSV بالأعمدة المالية نفسها، حتى 500 سجل في الطلب الواحد.
- **المراقبة:** عرض حجم التنبؤات، توزيع الاحتمالات، ومتوسطها، وإضافة النتائج الفعلية لاحقًا لتقييم الأداء.
- **واجهة عربية وAPI:** تجربة تفاعلية مع نسخة محفوظة من النموذج.

## البيانات والنموذج

استخدمت مجموعة [UCI Default of Credit Card Clients](https://archive.ics.uci.edu/dataset/350/default+of+credit+card+clients) التي تضم **30,000 سجل**. الهدف هو التنبؤ بمتغير **default payment next month**؛ أي التعثر في الشهر التالي، وليس احتمال السداد بعد التعثر.

خطوات العمل في [`notebooks/full_lifecycle.ipynb`](notebooks/full_lifecycle.ipynb):

1. فحص جودة البيانات والتحليل الاستكشافي (**Data Quality Checks / EDA**).
2. تقسيم طبقي إلى **Train / Validation / Test** بنسبة 60% / 20% / 20%.
3. **Feature Engineering** من سجل الفواتير والمدفوعات وحالات التأخر؛ 19 مدخلًا ماليًا و3 مؤشرات مشتقة.
4. مقارنة **Dummy Classifier** و**Logistic Regression** و**HistGradientBoostingClassifier**، واختيار النموذج وفق **PR-AUC** على مجموعة التحقق.
5. معايرة الاحتمالات باستخدام **Sigmoid Calibration** وتقييمها على مجموعة اختبار منفصلة.
6. تفسير المتغيرات باستخدام **Permutation Importance**.

### نتائج مجموعة الاختبار

| المقياس | النتيجة |
| --- | ---: |
| ROC-AUC | 0.7777 |
| PR-AUC (Average Precision) | 0.5538 |
| Brier Score | 0.1353 |
| نسبة حالات التعثر المكتشفة ضمن أعلى 20% من الدرجات | 50.34% |

هذه النتائج تخص تقسيمًا عشوائيًا لبيانات تاريخية، وليست تقييمًا زمنيًا أو دليلًا على صلاحية النموذج للاستخدام الائتماني الفعلي.

## التشغيل محليًا

يتطلب التشغيل Docker Desktop مع Docker Compose:

```bash
cp .env.example .env
# راجع قيم الإعدادات في .env قبل التشغيل
docker compose up --build
```

افتح: **http://127.0.0.1:8000**

إذا كان المنفذ `8000` مشغولًا، غيّر منفذ الجهاز في `compose.yaml` من `127.0.0.1:8000:8000` إلى `127.0.0.1:8001:8000`، ثم افتح `http://127.0.0.1:8001`.

لإيقاف التطبيق:

```bash
docker compose down
```

## حدود المشروع

- بيانات التدريب من تايوان عام 2005؛ وقد تختلف الأنماط والسلوكيات الائتمانية باختلاف السوق والزمن.
- لا تتوفر تواريخ قرار مناسبة لاختبار زمني مستقل.
- تتطلب مراقبة الأداء الفعلي وصول النتائج الحقيقية لاحقًا؛ ومؤشرات تغير التوزيع وحدها لا تثبت تراجع أداء النموذج.
- التطبيق نموذج بحثي، ويحتاج تحققًا إضافيًا وحوكمة وضوابط تشغيل قبل أي استخدام في قرارات تمس الأفراد.
