# مرصد المخاطر · RiskScope

تطبيق عربي لتجربة **احتمالية تعثر سداد البطاقة الائتمانية في الشهر التالي**، مع تحليل فردي ودفعات CSV، ولوحة لمراقبة التنبؤات وتغير توزيعها وربطها بالنتائج الفعلية. يتضمن [دفتر Jupyter شاملًا](notebooks/full_lifecycle.ipynb) من استكشاف البيانات إلى التدريب والتقييم والنشر التجريبي.

> النموذج مبني على بيانات تايوانية تاريخية من 2005. هذه منصة عرض وتقييم تقنية، وليست نظام قرار تحصيل أو نموذجًا معتمدًا لمحفظة سعودية. لا تدخل بيانات شخصية أو سجلات عملاء حقيقية قبل موافقة الجهات المختصة والتحقق الأمني والتنظيمي.

## تشغيل محلي على Mac

تحتاج Python **3.12**. إذا ظهر `Python 3.9.6`، اختر Python 3.12 عند إنشاء البيئة؛ إصدار NumPy المثبت هنا لا يعمل على 3.9.

```bash
cd /path/to/credit-risk-platform
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
python scripts/init_config.py
python -m app.server
```

افتح `http://127.0.0.1:8000`. افتح ملف `.env` محليًا، وانسخ `APP_API_KEY` و`APP_ADMIN_KEY` إلى زر **إعداد مفاتيح الوصول** في الواجهة. يحتفظ المتصفح بهما طوال الجلسة فقط. لإنهاء الخادم اضغط `Ctrl+C`.

إذا أردت تشغيل الدفتر بشكل مستقل داخل البيئة نفسها:

```bash
python -m pip install jupyterlab ipykernel matplotlib==3.10.8 xlrd==2.0.1
python -m jupyter lab
```

افتح `notebooks/full_lifecycle.ipynb`. بيانات الدراسة مضمّنة فيه؛ لا يحتاج ملف XLS منفصلًا.

## تشغيل بالحاويات

من جذر المشروع، ثبّت Docker مع Compose، ثم:

```bash
python3 scripts/init_config.py
docker compose up --build -d
docker compose ps
```

تعمل الواجهة محليًا على `http://127.0.0.1:8000`. يربط Compose المنفذ بعنوان الجهاز المحلي فقط، ويحفظ سجلات التنبؤ في Docker named volume اسمه `risk_state`. `GET /healthz` للتحقق من تحميل النموذج وقاعدة البيانات. لتشغيلها من خارج الخادم يلزم إعداد HTTPS ووسيلة تحكم بالوصول من خلال reverse proxy، وإدارة أسرار منفصلة قبل إتاحة الخدمة.

## طريقة الاستخدام

1. من **تحليل سجل** جرّب «ملء مثال تجريبي» ثم «حساب احتمالية التعثر». تُعرض النتيجة ومعرّف تنبؤ فريد.
2. من **تحليل دفعة** حمّل قالب CSV وأرسل حتى 500 صف. ملف النتائج يحوي `prediction_id` والاحتمال فقط؛ احتفظ بربط المعرّف مع النتيجة اللاحقة في نظام مصرح به.
3. من **المراقبة** تابع عدد الطلبات ومتوسط الاحتمال وتوزيع النتائج ومؤشر PSI. يمكن إضافة نتيجة فعلية `0/1` إلى معرّف واحد. تظهر PR-AUC وROC-AUC وBrier والتقاط أعلى 20% عندما تتوفر 30 نتيجة فعلية على الأقل وتوجد الحالتان.

لا تُخزن المدخلات المالية الخام في SQLite؛ يُحفظ معرّف عشوائي، وقت التنبؤ، الدرجة، نسخة النموذج، ومعرّف الدفعة والنتيجة الفعلية إن أُضيفت. لا تسجل الخدمة المفاتيح أو محتوى الطلبات في سجل الوصول الخاص بها. احتفظ بنتائج الدفعات في مكان آمن؛ CSV الناتج يحمل معرّفات والدرجات.

## API

`X-API-Key: <APP_API_KEY>` مطلوب لـ `POST /api/predict` و`POST /api/batch`. `X-Admin-Key: <APP_ADMIN_KEY>` مطلوب لـ `POST /api/outcome` و`GET /api/monitor?days=30` و`GET /metrics`. توفر `GET /api/schema` أسماء المتغيرات وحد الدفعة.

```bash
curl -H "X-Admin-Key: YOUR_ADMIN_KEY" http://127.0.0.1:8000/api/monitor
```

قدِّم 19 متغيرًا ماليًا JSON بأسمائها كما في القالب؛ التطبيق يحسب 3 ميزات مشتقة بالطريقة نفسها المستخدمة أثناء التدريب. `/metrics` يعرض عدّادات Prometheus الإجمالية فقط؛ الاستجابة تتطلب مفتاح الإدارة. اربط أداة المراقبة على شبكة موثوقة، واضبط رؤوس المصادقة فيها خارج ملفات المشروع العامة. مراقبة صحة الخدمة يمكن أن تستعلم `/healthz` بلا مفتاح.

## النسخ الاحتياطي والاحتفاظ

على التشغيل المحلي:

```bash
python -m scripts.maintenance --backup
python -m scripts.maintenance --purge-older-than 365
```

النسخ يستخدم واجهة SQLite online backup ويضع الملفات في `backups/`، وهي مستبعدة من Git. على Docker، قاعدة البيانات في volume؛ شغّل النسخ بطريقة معتمدة للوحدة وخزّن النسخة في موقع منفصل مع صلاحيات ومدة احتفاظ محددتين. اختبر الاسترجاع دوريًا. تغيير نسخة النموذج المضمّنة يتطلب بناء صورة جديدة وتوافق مخطط الميزات.

## اختبارات المشروع

```bash
python -m unittest discover -s tests -v
```

تتحقق الاختبارات من الخدمة الفعلية باستخدام النموذج المضمن وSQLite مؤقتة، المصادقة، التحقق من المدخلات، الدفعات، إدخال النتائج، ومؤشرات المراقبة. `node --check web/app.js` يتحقق من صياغة JavaScript إن كان Node مثبتًا. بناء Docker لم يُختبر ضمن بيئة إنشاء المشروع إذا لم يكن Docker متاحًا لديك.

## قبل أي استعمال فعلي

- البيانات المستهدفة هنا **تعثر البطاقة الشهر القادم**؛ لا تستنتج منها احتمال سداد دين قائم بعد التواصل أو أثر أسلوب التحصيل.
- اجمع بيانات محفظة مصرح بها مع تاريخ مرجعي وتعريف واضح للنتيجة، وتحقق بتقسيم زمني، ومقارنة مستقلة، ومعايرة، وإنصاف، وقابلية تفسير، وقياس أثر إجراءات التواصل تجريبيًا.
- العتبتان 100 درجة و30 نتيجة تسمحان بعرض المؤشرات فقط، وليستا ضمانًا إحصائيًا لكفاية العينة. PSI يتغير مع حجم العينة ولا يثبت تدهور الأداء. تحقق من تأخر وتحيز وصول النتائج الفعلية.
- هذا خادم عقدة واحدة وSQLite. للنشر عالي الحمل أضف إدارة مفاتيح مؤسسية، TLS، معدل طلبات، سجلات تدقيق محمية، مراقبة وتنبيهات مستقلة، إدارة تغييرات النموذج، اختبارات أمان، تخزينًا مدعومًا، وخطة استجابة للحوادث.
